# Local guest workers

Verified guests may run local `blob:` workers for computation. Both the packaged top document and the opaque guest document permit `worker-src blob:`; the guest otherwise retains its existing CSP and `sandbox="allow-scripts"`. No `allow-same-origin`, direct network origin, native operation, grant or NAP domain is added.

The policy permits blob URLs; it does not prove the provenance of a blob payload or make its code trusted. The inspected Mapplets release constructs its worker from modules embedded in its signed HTML. All other worker payloads remain untrusted.

A local worker inherits the policy container of its creator. `connect-src 'none'` blocks direct fetch and WebSocket traffic; the existing script policy blocks external imports. Data and remote worker scripts stay denied. A worker does not receive the parent window, DOM, injected NAP namespace, private bootstrap port or native bridge. A guest may explicitly send ordinary data to its worker and remains responsible for that data. NAP operations must still originate through its existing scoped endpoint.

CSP cannot distinguish dedicated and shared workers. Chromium currently rejects SharedWorker in this opaque context; WebKit permits a local blob SharedWorker. Do not describe this profile as dedicated-only. Worker lifetime and local CPU/memory are browser-managed, not a new host quota or guaranteed immediate termination boundary. Normal endpoint teardown and native revocation remain independently enforced. No service-worker origin or cross-origin credentials are restored. The opaque Window and worker IndexedDB stay unavailable. Chromium also denies worker CacheStorage, but WebKit allows local worker CacheStorage operations: a dedicated worker can put and read its own synthetic value. Tests preserve that positive control while verifying that parent data is invisible and another opaque frame or replacement document cannot read the value. Do not claim that all worker storage APIs are absent. Cache data, CPU and memory remain browser-managed without a new hard per-guest quota. The iOS host selects a fresh nonpersistent WK data store; native WK worker behavior and lifecycle acceptance remain a separate validation scope.

The protocol remains the selected [NIP-5D draft](https://github.com/dskvr/nips/blob/c041f84667c1781c3c1d5bfbd970943131b38cc9/5D.md). Its worker-denying CSP is an advisory example; opaque sandbox and exact source/port identity are required. Browser policy-container and worker ownership rules are defined by [HTML](https://github.com/whatwg/html/blob/5fcc2318395821db61e353705e6368ad9a000af5/source) and [CSP](https://github.com/w3c/webappsec-csp/blob/251d288dad4d6166e73541877ca2073864edeb8f/index.bs).

SharedWorker network regressions use a counted loopback endpoint and an unrestricted positive control; browser automation routing alone is not a network observer for that worker type.
