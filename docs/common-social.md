# Common social actions

The selected NAP-COMMON social profile implements follow, unfollow, native-event reactions and reports. The owning draft is [NAP-COMMON8cd0eae](https://github.com/napplet/naps/blob/8cd0eae8550575771bb616a384e2dfbcade31673/naps/NAP-COMMON.md). It maps to NIP02 kind3, NIP25/30 kind7 and NIP56 kind1984. Identity, consent, native signing and publication stay with the shell.

## Reviewed authority

Social actions require an actual Common grant, Identity, and either Relay or Outbox. This is a selected shell profile: the draft declares Relay, while this host also permits its independently reviewed Outbox route. Raw Relay is never inferred from Outbox. A selected signing method in saved native metadata is required even for an idempotent modifying call. This is not a network or OS connectivity probe; actual availability is checked at approval/signing. No method fallback is introduced. Public Common helpers and current reads keep their previous requirements.

Existing Common-read pins keep read-only authority. An already mounted exact napplet is reused without broadening its grant. Close that card and open it freshly from Discover to request the new review; merely refocusing it does not enable writes. Fresh social access requires normal napplet review, even when the domain arrays are identical or dependencies are split between required and optional declarations. A trusted native-only `commonProfile: social-v1` derives from the effective reviewed admission, not a guest request or compiled support label. Absence is read-only. Unknown values, bundled callers and incomplete dependency sets are refused. Native approval captures bind the original action/targets, identity, epoch, generation, publisher/app/version and prepared exact event/destinations.

## Operations and bounds

Follow/unfollow accept1–16 public npubs before deduplication. A fresh complete signed own kind3 read supplies the basis; cached Identity follows are not a mutation basis. Preserve its content, unrelated tags, order and retained p-tag metadata. Add missing targets or remove every matching p tag. Never truncate a list. An unchanged result returns ok without an event, review, signature or publication. Complete observed absence permits an empty basis; incomplete, invalid or unavailable data does not.

A modifying replacement must have a timestamp strictly later than its selected basis, so a same-second NIP01 ID tie cannot discard the change. Same-second edits wait only to the next local second within the original planning deadline; a future-dated basis is refused. The fresh complete basis is read again before signing; any different selected ID cancels the review. This is bounded observed-basis behavior, not cross-device atomic compare-and-swap. A concurrent change after the final check cannot be prevented by NIP02.

Reactions resolve and verify the exact native event, derive e/p tags and an address coordinate for addressable targets, and accept plus/minus, one bounded Unicode emoji sequence, or one NIP30 shortcode with a matching HTTPS emoji tag. The image URL is metadata only and is never fetched by this operation. Reports use a selected NIP56 reason and up to4096 UTF8 bytes of text. Event reports resolve the author and reject a supplied mismatch; pubkey reports normalize public npub/hex. Caller relay strings are bounded advisory metadata and never introduce destinations.

Every changed signed EVENT must fit the existing8192-byte native publication frame, including its pubkey, ID and signature. Large real follow lists can exceed that limit even though the incoming event reader accepts a larger signed event. Such a mutation returns follow-list-too-large before review/sign/send; the shell does not truncate it or raise Raw Relay/Outbox limits. Empty test accounts therefore do not establish populated-account compatibility.

Preparation has a15-second deadline including signer metadata and public reads/routing. A user has one pending social mutation; the planner holds at most two users, inside existing approval queue bounds. Ignored/late I/O cannot retain ownership or prepare after cancellation. Native review/signing retains the existing600-second lifetime and matched660-second client backstops. Close, focus/background changes, identity replacement, expiry and revocation keep existing native approval fences. Native per-event approval is mandatory; a guest cannot approve or manufacture a lease.

When Outbox is actually granted, social preparation uses its bounded routing for both public reads and publication, including the normal configured Network fallback where selected. Relay-only callers use configured Network reads/publication. A complete verified basis is complete only within those selected peers; it is not a global latest-list guarantee. There are no guest destinations, recipient-inbox expansion or ancillary relay-list broadcasts. Publication reuses the existing native bounded one-use event/relay pairs. A positive ACK yields the original Common result with exact event ID/event. A lost result is publication-result-unknown and retains close-risk handling; it is not a known failure and never causes an automatic retry. Cancellation after possible dispatch cannot retract an event.

## Evidence scope

Deterministic signed fixtures and native semantic/lease proofs cover normalization, preservation, no-op zero effects, original correlation, changed basis, missing dependencies/signer, cancellation and stale completion, size bounds and unknown outcomes. Isolated browser tests verify the four actual SDK shapes and approval timeout retention. Native host-core compilation and supplied-byte tests are separate from ordinary Android/iOS approval, signer and public relay acceptance. No public signing or publication is required by these tests.
