# Encrypted CVM foreground requests

This selected profile implements the draft [NAP-CVM revision 28cf1bdb](https://github.com/napplet/naps/blob/28cf1bdb5c6412bfbfcecb79a5a5121e18376f2f/naps/NAP-CVM.md), with encrypted CEP-4 envelopes, free-only CEP-8 handling and bounded CEP-41 receiver controls. The profile is integrated in the shell. Compilation and controlled fixtures do not establish ordinary provider acceptance.

A published napplet needs a newly reviewed CVM grant and native `free-foreground-v1` registration. Existing finite Media and Common social grants retain their exact effective authority and cannot acquire CVM silently. Reopening a saved old pin retains its old grant; an already mounted instance is not upgraded. There is no selected vault key or signing-method dependency. A fresh native-only ephemeral client key and a new wrapping key sign and encrypt each fixed kind-25910 request inside a kind-1059 envelope.

Every request, notification and server response has a separate trusted native review showing the requesting napplet, exact publisher/version, provider, relay and complete MCP bytes. The sheet explicitly explains that the source napplet may continue while another card is in use, and stops on background, account change or closing the source napplet. Payments through Hypergolic are unavailable. Free provider tools may still have external effects; approval is for the shown operation and arguments, not a promise about a provider's business behavior.

## Selected behavior

- `request`, `close`, endpoint-owned events, tool wrappers and resource wrappers are implemented. Resource reads preserve every returned text/blob content entry. Raw MCP notifications and responses resolve `null` after correlated relay acknowledgement; full requests require an authenticated, correctly correlated MCP response.
- MCP initialization selects `2025-06-18`, advertises empty client capabilities and sends initialized before the approved business message. Initialization can be disabled explicitly. No roots, sampling or user-signing service is advertised. Initialization uses a fresh public UUID correlation, never an approval/session handle; a collision is regenerated without rewriting the caller ID. Cancellation notifications must target an active dispatched client request of this exact endpoint/server and are rechecked after review and immediately before publication; initialization and the opposite request direction are excluded.
- The public event wire is `{server,message}`. The injected binding accepts a single event argument and the pinned SDK 0.31.1 two-argument `(server,message)` callback, selected by callback arity. Registration alone opens no transport.
- Discovery and registry list/describe/call return explicit unsupported errors; registry `has` returns false. This is not registry availability advertising.
- The selected implementation uses the first exact reviewed relay. It does not replay an uncertain request on another relay, discover different providers or silently substitute the publisher's localhost endpoint. Missing relay hints use at most four configured Network defaults, captured before review. Relay DNS, public addresses, hostname TLS and bounded WebSocket framing stay native-owned.
- A session context closes when its original operation completes; no long-term idle provider subscription or initialization reuse is promised. A separately reviewed side notification/server response may use the still-active context. Endpoint close cancels its pending work and never transfers authority to another napplet.

The private carrier includes a method label and serialized progress-token metadata so iOS never has to Foundation-decode arbitrary MCP argument JSON. The trusted runtime derives those fields from its immutable public MCP capture; the trusted app ingress independently parses the full original bytes and rejects any method/token mismatch before exposing review or approving a native permit. Guests cannot supply these private fields through the public CVM schema. The native permit binds the complete unchanged message bytes, source and provider; labels never replace that binding. The return event lane similarly validates and captures the public event in the app, derives its provider, and wraps the unchanged JSON as an opaque string in a private `{provider,message}` carrier. Native delivery checks the exact request token, registration revision and provider without Foundation-decoding arbitrary event data. A native delivery denial cancels the owning operation rather than silently losing notifications. Native CEP-41 emission is limited to fixed templates with the captured scalar token. Progress tokens use the existing 128-character string/safe-integer ID profile (at most 1 KiB serialized metadata). Escaped lone-surrogate argument and token bytes are preserved; nonce bounds count JSON string bytes without lossy decoding.

## Bounds and ownership

The native whole-operation budget starts on first ingress, before React Native delivery, review, initialization and transport. It defaults to 30 seconds and can be requested up to 120 seconds; it never renews after review, progress or a focus change. JavaScript's small terminal-delivery margin cannot authorize further native emission.

The profile permits 32 KiB of logical MCP JSON, 64 KiB per signed event and 66 KiB per WebSocket text, with a 4 MiB cumulative wire budget, 4,096 frames and 2,048 texts. Encrypted/escaped envelope amplification can reach the tighter event bound before a 32 KiB message. CEP-41 payloads are bounded to 2 MiB, 16 reorder gaps and 64-byte nonces. There is one full RPC plus one side publication per endpoint, two process-wide native key/socket reservations, four native pending/approved operations and at most two per exact source. Native source registrations are bounded to 64 in the single process composition. No arbitrary encrypted-event signing/decryption/socket API is exposed to guests or the bridge.

Native prepare returns an opaque plan and inner event ID before commit may emit. The trusted app installs response correlation first. Commit rechecks the exact source/provider/deadline and consumes an approved business permit once immediately before emission. Incoming outer and inner signatures, hashes, kinds, recipient, server, times and byte bounds are checked natively; the app then captures immutable MCP structure, IDs, event references and stream/payment state before delivery. Malformed or mismatched responses fail closed, with no permissive signature fallback.

Logical close acknowledges revocation, not physical resource destruction. A bridge cleanup failure still attempts every affected local cancellation and native close; the first failure remains an unknown native outcome. Native capacity stays reserved until the key, socket, network callbacks and any entered DNS worker actually unwind. Unknown cleanup stays reserved. Background/account/source revocation is irreversible for old contexts, even after foreground return. Other capabilities retain their existing focus rules; this dedicated service permit does not change Identity, Relay, Outbox, Upload or Media authority.

## Evidence and remaining acceptance

Shared and browser fixtures cover contracts, wrappers, long-lived native projection, sender/generation binding, explicit review denial, deadline and close races. Native module compiles include the actual host views and Expo routes. Owned native proofs use programmatic test approvals, controlled/in-memory transport and disposable generated test keys; they do not prove a real native consent gesture, provider behavior or public effects. Ordinary final Android/iOS consent, paired-source unfocused operation, foreground/background/revocation and an explicitly approved provider request remain acceptance work on the final ordinary builds.

The exact original Kipinä agent publication also uses `ws://localhost:3334` for its journal. That is an independent publisher destination dependency; this profile does not reroute it or authorize local/private networking. Its prompt/history workflow may publish journal records before CVM. A local-only controlled CVM proof is not a successful ordinary paired-agent primary workflow.
